# scripts/

Тулинг, которым собирается пакет. Источник истины — каталог `svgs/`; всё
остальное (`fonts/`, `lib/src/**`, `assets/icon-preview/`, `example/lib/icon_registry.dart`)
из него генерируется и коммитится в репозиторий.

Все скрипты вычисляют корень репозитория от своего расположения — запускать
можно из любой директории.

## Конвейер

```
cdn.iconsax.io
      │  download_icon_parts.py      каталог иконок → scripts/.cache/
      ▼
all_icons_data.json
      │  download_svgs.py            скачать + расшифровать SVG
      ▼
   svgs/                             ◀── источник истины
      │  generate_fonts_api.py       SVG → шрифты + Dart API
      │    └─ сам вызывает fix_font_metrics.py и fix_layer_opacities.py
      ▼
fonts/ + lib/src/**
      │  generate_example_registry.py
      │  generate_previews.py
      ▼
   готовый пакет
```

## Каталог иконок

`all_icons_data.json` — выгрузка с CDN: для каждой иконки `style`, `category`,
`tier` (`free`/`pro`) и путь на CDN. Нужен не только для скачивания, но и для
разрешения коллизий имён: если внутри стиля короткое имя встречается больше
одного раза, к нему добавляются последние 4 hex-символа md5 от CDN-URL.

Лежит в `scripts/.cache/all_icons_data.json` (13 МБ, вне git). Переопределяется
переменной окружения `ICONSAX_CATALOGUE`.

Сами скрипты в git есть — иначе пайплайн не воспроизводится из чистого клона. В
публикуемый на pub.dev пакет они не попадают: за это отвечает `.pubignore` в
корне, который исключает `scripts/` и `svgs/`. Учтите, что корневой `.pubignore`
**заменяет** `.gitignore` при публикации, а не дополняет его, поэтому в нём
продублировано всё остальное (`build/`, `node_modules/` и т.д.).

## Основные

### `download_icon_parts.py`
Тянет `icons_part_1..10.json` с `cdn.iconsax.io/icons_parts/`, склеивает и кладёт
в кэш.

### `download_svgs.py`
По каталогу скачивает все `tier == free` иконки. Файлы на CDN зашифрованы
AES-256-CBC в формате OpenSSL (`Salted__` + пароль `123qwe`), скрипт их
расшифровывает и раскладывает в `svgs/<style>/<category>/<имя>_<ключевые-слова>.svg`
(имя файла с CDN как есть; у части файлов хвост `-temp`). 100 потоков, 3 попытки
на файл.

> Скрипт **заменяет `svgs/` целиком**. Если каталог непустой, он откажется
> работать без явного `--force`.

### `generate_fonts_api.py`
Главный генератор. Бьёт SVG на батчи (по 4 для `twotone`, иначе по 50), шлёт на
`app.iconsax.io/api/svg-to-code`, при ошибке рекурсивно делит батч пополам.
Полученные TTF чистит от `GSUB`/`GPOS`/`GDEF`, сливает через `fontTools.merge` и
пишет:

- `fonts/iconsax_<style>.{ttf,woff,woff2}`
- `lib/src/static/<style>.dart` — «сырые» `IconData` по одному на глиф
- `lib/src/iconsax_<style>.dart` — публичный класс; для `bulk`/`twotone` это
  композитные `IconsaxIconData` со списком слоёв
- `lib/src/static/iconsax_data.dart`, `lib/src/static/iconsax_resolver.dart`
- `lib/iconsax.dart`

Последним шагом сам прогоняет оба repair-скрипта (ниже) — эндпоинт и логика
сборки списков оставляют после себя два дефекта, и чинить их вручную каждый раз
незачем.

`lib/src/iconsax_widget.dart` он **не трогает**: раньше виджет писался из
встроенного шаблона, и любая регенерация молча откатывала правки в нём. В виджете
нет ничего, что выводится из SVG, поэтому он живёт в git как обычный исходник.

## Repair-проходы

Оба идемпотентны и понимают `--check` (проверить без записи, ненулевой код
возврата при находках). Вызываются генератором автоматически; вручную нужны,
только если правился уже собранный результат.

### `fix_font_metrics.py`
Эндпоинт отдаёт **правильные контуры**, но пишет `hmtx.leftSideBearing = 0`
каждому глифу, хотя реальный `xMin` доходит до 188 из 200 юнитов em.
Растеризатор двигает глиф так, чтобы `xMin` совпал с `lsb`, — и иконка уезжает
влево: 1–2 px при размере 24 у однотонных стилей, 6–22 px у каждого слоя
`bulk`/`twotone` (слои при этом ещё и расходятся между собой).

Что делает:
1. `lsb = xMin` для всех глифов — основная правка, контуры не трогаются;
2. полный em в advance width;
3. центрирует 9 иконок, у которых исходный viewBox не 24×24 (эндпоинт прижимает
   их в угол em);
4. обнуляет `typoLineGap` (было 18/200 — смещало многослойные иконки вниз на ~9%)
   и пересчитывает производные поля `head`/`hhea`/`OS/2`;
5. перезаписывает `.ttf`/`.woff`/`.woff2`.

### `fix_layer_opacities.py`
Генератор строит два списка `IconsaxIconData` в **разном порядке** и спаривает их
позиционно: `icons` отсортирован по кодпоинту, `opacities` — в порядке документа
SVG. Где порядки расходятся, тень 0.4 попадает не на тот слой. Плюс
`<g opacity="0.4">` разворачивается в дочерние пути, и собственная прозрачность
группы теряется.

Скрипт перечитывает слои из SVG: спускается сквозь обёрточные `<g clip-path>` (у
них нет своего `opacity`), а на нужном уровне каждый `<path>` = `pathN`, каждый
`<g>` = `groupN` — ровно те имена, что даёт эндпоинт. Слои выдаются в порядке
документа, который заодно является правильным порядком отрисовки (первый —
нижний), каждый со своей прозрачностью. Набор слоёв у иконки не меняется —
только порядок и прозрачности.

## Постобработка

### `generate_example_registry.py`
Собирает `example/lib/icon_registry.dart` — `Map<String, IconData>` /
`Map<String, IconsaxIconData>` на стиль, чтобы галерея в примере могла
перечислить иконки по именам.

### `generate_previews.py`
Рендерит `assets/icon-preview/<style>/<getter>.png` и подставляет ссылку
`/// ![](...)` в docstring каждого геттера публичного класса.

Растеризация идёт через FreeType (Pillow), то есть тем же движком, что и у
Flutter, и с той же геометрией, что у виджета `Icon`: em-бокс — это бокс иконки,
advance центрируется в нём, базовая линия на нижней грани. Превью показывают
реальное положение, а не обрезку по чернилам, поэтому кривое выравнивание на них
видно. `bulk`/`twotone` собираются стеком слоёв с их прозрачностями — как в
`IconsaxIcon`.

Флаги: `--styles`, `--limit N` (рендерит N иконок на стиль и не трогает Dart —
для быстрой проверки), `--no-dart`.

> Сейчас в репозитории лежат превью только для `bold` и `outline` (1124 и 1118
> штук), сгенерированные старой версией скрипта. Для остальных четырёх стилей
> картинок нет, так что ссылки в их docstring битые. Полный прогон создаст
> ~6700 PNG — решение по объёму за вами.

## Диагностика

| Скрипт | Что показывает |
|---|---|
| `check_duplicates.py` | по стилям: сколько уникальных коротких имён, файлов, и сколько коллизий с **разным** содержимым |
| `count_free_icons.py` | статистика по каталогу: сколько free-иконок, разбивка по стилям/term/tier |

## Зависимости

`fonttools`, `brotli` (шрифты), `pillow` (превью), `cryptography` (скачивание
SVG). `generate_fonts_api.py` и `fix_font_metrics.py` доставляют fonttools/brotli
сами.

## Известные проблемы, которые скрипты не чинят

При слиянии батчей в `generate_fonts_api.py` часть глифов теряется из-за
коллизий кодпоинтов и имён:

- **66 иконок** есть в `svgs/`, но недостижимы в шрифтах (`bold/heart`,
  `linear/blur`, `outline/eye`, `bulk/call` и др.);
- **755 слоёв в `bulk` и 475 в `twotone`** есть в SVG, но их глифов нет в шрифте,
  поэтому иконки рисуются неполными (например, `bulk/archive-minus` — только
  `path2`, `bulk/save-minus` — только `path3`).

Лечится только регенерацией с починенной раздачей кодпоинтов, а это меняет
кодпоинты, то есть breaking change для пользователей пакета.

Отдельно: `lib/src/static/iconsax_data.dart` (381 КБ) генерируется, но нигде не
импортируется и не экспортируется из `lib/iconsax.dart` — мёртвый файл.
